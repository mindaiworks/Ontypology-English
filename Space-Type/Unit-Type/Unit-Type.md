## Chapter One　Property and Attribute Value

![image3](assets/image3.jpg)

> *Chapter Imagery・The Axis of Property—Dimensions and Graduations*

A property is "a question that can be asked." It has no answer in itself; it merely delimits a range of "what is to be asked." An attribute value, on the other hand, is the actual answer to that question in some concrete situation—the individual options circled out beneath the property. By way of analogy: a property is like the column heading of a blank table, reading "material"; an attribute value is the content actually filled in beneath that column, such as "ceramic." The heading itself does not change, but the answers that can be filled in beneath it vary with the concrete object.

**Table 1-1　A Comparison of Property and Attribute Value**

|  | **Property** | **Attribute Value** |
| --- | --- | --- |
| **Positioning** | A question that can be asked | The question's actual answer in a concrete situation |
| **Analogy** | A table's column heading ("material") | The content actually filled in beneath the column ("ceramic") |
| **Change** | The heading itself does not change | Varies with the concrete object |

### 1.1　How Properties Gradually Emerge—Using a Cup as an Example

**Step One:** Two cups are placed side by side, their difference and similarity are detected, and the difference is found to fall in only one place: transparent versus blue. The only property to emerge at this stage is "color," with attribute values {transparent, blue}.

**Step Two:** A third cup (ceramic, blue, with a handle) is added. Look first at the color blue—the existing color axis already has this option, so it is attached directly, and the color axis needs no change. But this cup simultaneously brings two batches of new difference: the material changes from "glass" to "ceramic," and this batch of difference does not match up with the dimension of color, so it forces out a second property, "material." Furthermore, this cup has a handle, whereas the first two cups had nothing at all that could be compared with it; this difference likewise matches up with neither color nor material, so it forces out a third property, "handle."

Once "material" and "handle" are established, the first two cups must also have values backfilled for these two properties: material is filled in as "glass" (it was glass all along, it just did not need to be said before), and handle is filled in as "N" (it never had one, there was just nothing to compare against before). Once a property is extracted, it must be applied to all individuals that have already appeared; it cannot be that only the newly arrived object has it while the rest remain blank, because a property is a dimension, and a dimension must run through all individuals in order to be used for mutual comparison.

**Step Three:** A fourth cup (glass, transparent, with a handle, with a lid) is added. Color, material, and handle can all match up with the existing axes; only the difference "lid" has nothing in the first three cups to correspond to, so it forces out a fourth property, "lid," and "N" is likewise backfilled for the first three cups.

**Step Four:** For cups added thereafter, whether the color becomes gold, silver, beige, khaki, white, or gray, or the material becomes stainless steel or paper, all these differences can match up with the two existing dimensions of color and material. Therefore one need only add new attribute values beneath the corresponding properties, and there is no need at all to open a new property; handle and lid likewise continue to be recorded as Y／N, and no fifth new property will pop up, because all differences observed so far can already be accommodated by these four dimensions.

![image4](assets/image4.png)

> **Figure 1-2** A timeline of properties emerging as cups are added one by one

![image5](assets/image5.png)

> **Figure 1-3** The four stages of property emergence and a consolidated property–attribute value master table

Finally, everything is consolidated into one complete property–attribute value master table:

**Table 1-2　Property–Attribute Value Master Table**

| **Property** | **Attribute Value** |
| --- | --- |
| Material | Stainless steel, ceramic, paper, glass |
| Color | Transparent, blue, gold, silver, beige, khaki, white |
| Handle | Y／N |
| Lid | Y／N |

From this a rule can be induced: the moment a property emerges is always the moment "this batch of difference matches up with none of the existing properties"; the moment an attribute value increases is simply when "the nature of the difference matches up with some existing property," in which case it is put straight in. Moreover, every time a property emerges, it is accompanied by retroactively applying this new dimension to all individuals that already exist, so that each individual has a definite value on every property; only then is this structure complete, without holes.

This rule can be formalized as a decision procedure: when a new object is brought up against existing objects, first ask "the nature of this batch of difference—which existing property does it agree with?" If the answer is "it agrees with some property," then simply add a new attribute value beneath that property, without touching the Framework; if the answer is "it agrees with none of the existing properties," then a new property must be opened, and this new property backfilled for all individuals that already exist. This procedure guarantees the completeness of the property structure: every individual has a definite value on every property, and no hole such as "some cup is blank on some property" can appear.

This mechanism also explains why the number of properties is usually far smaller than the number of attribute values: a property is a "dimension," representing a "kind" of difference; an attribute value is an "option," representing the various possibilities within one kind of difference. In our cup example there are only 4 properties (color, material, handle, lid), yet the attribute values keep expanding as the number of cups increases (color grows from 2 values to more than 7). This is like a coordinate system: the number of axes is fixed (two-dimensional is two-dimensional), but the graduations on each axis can extend indefinitely.

> **Property Emergence Rule (Summary)**
>
> **◆** Difference matches none of the existing properties → open a new property, and backfill all individuals that already exist.
>
> **◆** The nature of the difference agrees with an existing property → only add a new attribute value beneath that property.
>
> **◆** Few properties, many attribute values; dimensions are fixed, graduations can extend.

## Chapter Two　Space Collections

![image6](assets/image6.jpg)

> *Chapter Imagery・The Light of the Container—Boundary and Interior Space*

A Space Collection refers to: an object that has a definite boundary in space, where this boundary encloses a piece of "interior space," allowing other things to be put in and also taken out, while the container itself does not change who it is because of whether there is something in the interior space or what is inside it. In short, a container answers the question "where is the thing," not the question "what is the thing"; a cup does not become a different thing because it holds water rather than coffee—from beginning to end it is the same cup.

A Space Collection comprises three elements:

#### (1) Boundary

The boundary is the most core part of a container, and its function is to distinguish "inside" from "outside." A cup wall, a bowl body, the wall of a room, the fabric of a schoolbag, the stitching of a pocket—all are boundaries; a boundary need not be a solid physical body—a water surface, or a line drawn with chalk, can constitute a boundary as long as it clearly draws the distinction between "already in" and "not yet in." A boundary can be closed (like a sealed thermos bottle) or open (like a cup without a lid); whether it is open affects whether things can "fall out," but does not affect whether the container itself is a container.

#### (2) Interior Space

The interior space is the piece of space enclosed by the boundary and actually used to hold other objects; its size and shape determine what the container can hold and how much it can hold. The interior space can be empty (an empty cup is still a cup), and it can also hold several different things at once (a cup can hold water and ice cubes at the same time).

#### (3) Independent Identity

This is the most crucial and also most easily overlooked property of a Space Collection: a container's identity is not determined by its contents, but by its own boundary and structure. Because identity is independent of the contents, a container can go through the whole process of "put something in → take it out → put something else in," and each time it is still recognized as the same container. This is very different from the identity of ordinary things: if we replace the "water" in a cup of water with "coffee," we do not say "this cup of water became coffee," but rather "what is in the cup has changed" and "what changed is the contents," while "the container has not changed"—this feeling for the language already reflects the fact that a container's identity is independent of its contents.

![image7](assets/image7.png)

> **Figure 2-1** The three major elements of a Space Collection: boundary, interior space, independent identity

From this extends the relationship between container and contents: the contents are replaceable and removable, and do not in turn define the container; a container can have size limits, which is also where a container differs from "boundless space." In addition, containers can also nest inside one another—a cup can be put into a bag, the bag can be put into a box, the box can be put into a room; each layer of container stands independently on its own, each obeying the three basic elements of "boundary, interior space, independent identity."

> **Figure 2-2** Nesting of containers: cup into bag, bag into box, box into room—each layer stands independently on its own

## Chapter Three　Space Lists: BOM and SOM

![image9](assets/image9.jpg)

> *Chapter Imagery・Structural Blueprint—An Exploded View of Parts*

### 3.1　BOM (Bill of Materials)

The BOM answers "when this thing is opened up, what smaller things is it composed of"—a cup is composed of a cup body, a cup ear, and a cup lid. To obtain a BOM, one need only take an individual itself apart; there is no need to compare it with any other individual. Even if only this one cup existed in the world, as long as it has a handle and a lid, it can still be taken apart into "cup body + cup bottom + cup ear + cup lid"—this does not rely on comparison, it relies on disassembly.

The criterion for judging whether a feature should be listed in the BOM is only one: can it be taken off, and after being taken off, is it still a thing with an independent identity that can be recognized? Using this criterion, check a few features on the cup:

**Table 3-1　BOM Criterion Checklist—"After it is taken off, does it still recognize itself?"**

| **Feature** | **Verdict** | **Explanation** |
| --- | --- | --- |
| **Cup ear (handle)** | **Counts as BOM** | It can be taken off, and after being taken off it is still "a cup ear." |
| **Cup lid** | **Counts as BOM** | It can be taken off, and after being taken off it is still "a lid." |
| **Color** | **Property** | It cannot be taken off; removing the color does not leave "a portion of color that was taken off," the color simply disappears. |
| **Material** | **Property** | Likewise it cannot be taken off; material is "what the cup body is made of," not "what is contained inside" the cup body. |

![image10](assets/image10.png)

> **Figure 3-1** The boundary between BOM and property: what can be taken off goes into the BOM, what cannot goes into properties

This criterion clearly draws the boundary between BOM and property: what can be taken off, and is still an independent individual after being taken off, goes into the BOM; what can only be used to describe "what this thing itself looks like," and cannot be taken off, goes into properties.

This criterion can be expressed more concisely: "After it is taken off, does it still recognize itself?" If the answer is "it recognizes itself" (for example, a cup lid taken off is still a lid), then it goes into the BOM; if the answer is "it does not recognize itself" (for example, once the color is "taken off" it is nothing at all), then it goes into properties. This criterion applies not only to cups but to any object: a car's engine, tires, and doors, once taken off, are still "an engine," "a tire," "a door," so they are items in the car's BOM; but a car's color, brand, and year of manufacture cannot be taken off—they are the car's properties.

Taking the cup as an example, the BOM gradually emerges as the observed samples increase: the first cup (glass, transparent, no handle, no lid) is a continuous piece of glass as a whole, and taking away any part would not leave anything that could be independently named, so at this stage the BOM has only two items, cup body and cup bottom; the second cup (ceramic, blue, with a handle, no lid) has an additional handle that can be taken off, so the BOM increases to three items; the third cup (glass, transparent, with a handle, with a lid) has yet another lid, so the BOM increases to four items.

The BOM is responsible for answering "when this thing is opened up, what independently recognizable parts is it composed of"; properties are responsible for answering "what this thing itself (whether the whole, or some part in the BOM) looks like." The BOM determines how many branches the tree structure divides into downward; properties determine the appearance of each branch and each node itself. Only together can the two describe an individual completely, without omission.

### 3.2　SOM (Space of Materials)

**SOM ＝ BOM ＋ Space Collections**

The BOM can tell you "what parts can be taken apart," but it will not tell you how these parts are arranged in space, whether they depend on one another, or which part, if removed, would shake the whole. The BOM is a "list," not a "map." Space Collections are the opposite: they can tell you "there is a boundary, there is interior space," but whatever is placed in the interior space is treated as arbitrarily replaceable contents (swapping water for coffee makes no difference), and they cannot present the fact that "the parts have fixed positions relative to one another and depend on one another." What the SOM deals with is precisely the question that neither of these can answer and that only their superposition can: what space does this object occupy, and can the things in this piece of space be casually taken away?

What the SOM describes is: an object that simultaneously possesses the "boundary" and "interior space" of a Space Collection, but what is placed in its interior space is not arbitrarily replaceable contents, but rather parts that are fixed at specific spatial positions, structurally dependent on one another, and jointly constitute this object itself. In other words, the SOM is a "container," but what the container holds is not water—it is the container's own skeleton.

**The properties of the SOM are half inherited from Space Collections and half inherited from the BOM:**

**Table 3-2　The Inheritance Structure of the SOM**

| **Source of Inheritance** | **Inherited Properties** |
| --- | --- |
| **Inherited from Space Collections** | Boundary (distinguishing "the extent of this object" from "outside the extent"), interior space (the place the parts actually occupy and exist in), independent identity (having its own identity as a whole, rather than being a mere stacked list of parts). |
| **Inherited from the BOM** | Structural parts (what is in the interior space is not just anything that can be put in, but the parts necessary to constitute this whole), the dependency relations among parts (the parts have relations of support, connection, and attachment to one another, rather than being mutually independent and equal in status), and the fact that removing a part shakes the identity of the whole (unlike a container, once the SOM has a part removed, it very likely is no longer "the same thing"). |

Looking at the SOM with the cup as an example: the interior space (from Space Collections) is the space enclosed by the boundary, and it is not empty inside but filled with structural parts; the structural parts (from the BOM) are the cup body, cup handle, cup bottom, and cup lid, each occupying a portion of the interior space, and their positions relative to one another are fixed—the handle grows at the middle of the side, the bottom is at the very lowest, and positions cannot be casually swapped; the dependency relations (from the BOM) show themselves in that if the cup bottom disappears, the whole structure collapses and the cup is no longer a cup, and if the handle disappears, the cup can still hold water, but it is no longer the original "cup with a handle."

![image11](assets/image11.jpeg)

> **Figure 3-2** SOM ＝ BOM ＋ Space Collections: from parts list to structural map

This is a completely different level of description from the earlier, standalone "cup as container" (holding water, holding coffee)—a cup that holds water is looking at the cup as a Space Collection; how the cup itself is constituted by cup body, handle, and bottom is looking at the cup as an SOM. The two can hold at the same time; they simply answer two different questions respectively: "what guests are inside it" and "how this thing itself grew into being." The SOM places the originally abstract relation of "structure" back onto the concrete stage of "space," so that the dependency relations among parts are not merely a logical description, but an existence that can be seen, located, and actually occupy space.
